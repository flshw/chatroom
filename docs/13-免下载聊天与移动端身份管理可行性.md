# 免下载 Web 聊天 & 移动端身份管理 · 可行性分析

> 版本：v4 · 2026-11-14 · 对应需求：服务端第 4 项、客户端第 1 项

---

## 一、服务端「用户直接登录 / 导入 XML / 无需下载客户端」是否可行

### 结论：**完全可行，而且当前版本已经天然具备，只是没有显式入口。**

服务端 `server/src/http.js` 的 `/` 路由直接托管 `server/public/chatroom.html`（即打包好的单文件客户端）。局域网内任意浏览器访问 `http://<服务器IP>:8080/` 就已经是在线聊天，既不需要下载 HTML，也不需要安装任何东西。本轮补的是一个把这些能力讲清楚、组织好的门户页 `/welcome`。

### 1. 三种可选落地形态

| 形态 | 做法 | 安全性 | 本轮是否采用 |
|---|---|---|---|
| **A · 直接在线聊天** | 浏览器访问服务端 `/`，即运行托管版单文件客户端 | 私钥仅在浏览器内存，服务端只存公钥 | ✅ 已存在，门户页提供入口 |
| **B · 门户页 + 引导** | `/welcome` 提供：在线聊天入口、单文件下载（含 SHA-256）、使用说明、身份 XML 导入/导出步骤、管理台入口 | 同上 | ✅ **本轮实现** |
| **C · 服务端代管身份** | 用户把 XML 上传到服务端，服务端解密私钥并代替客户端完成注册 | ❌ **私钥离开用户设备**，管理员可读取，直接破坏「服务端只存公钥」与私聊 E2EE 边界 | ❌ 明确不采用 |

> 需求里的「服务端增加用户直接登录」如果理解为 C（把身份文件交给服务器代登录），**在安全上是倒退**：现有注册协议要求客户端用私钥对挑战码做 RSA-PSS 签名，正是为了证明「私钥仍在你手里」。一旦私钥上传，服务器就能冒充该用户发起私聊。因此本轮把该需求解释为「在服务端页面上直接登录聊天」（形态 A/B），并保留私钥本地化原则。

### 2. 身份 XML 导入在 Web 端的技术可行性

现有实现链路已全部具备，纯浏览器 API 即可，无任何服务端改造：

```
<input type="file"> → File.text() → DOMParser 解析 XML
  → 可选 PBKDF2+AES-GCM 解密 <keys> → forge.pki.privateKeyFromPem
  → 用私钥对 (uid|ts|challenge) 做 RSA-PSS 签名作为恢复证明
  → 服务端 identity.verifyResume() 用链上公钥验签 → 恢复同一 UID
```

关键点：**服务端只保存公钥**（`identities.pubkey` + 身份哈希链），私钥始终只在浏览器内存中。导入 XML 不产生任何「私钥上传」的网络请求，安全模型不变。

### 3. 风险与边界（必须在说明页告知用户）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 公共电脑残留 | 下载目录里可能留下明文 XML | 强烈建议设置「本地加密口令」；提供身份库一键删除 |
| 跨浏览器/跨设备不共享 | localStorage 与下载目录按浏览器隔离 | 提供导出 XML / 导入 XML，作为唯一可移植载体 |
| `file://` 混合内容拦截 | 双击本地 HTML 连 `http://IP` 可能被拦 | 门户页明确建议直接用 `http://IP:port/` |
| 局域网 `http://` 非安全上下文 | 原生 `crypto.subtle` 不可用 | 已用内联 node-forge 纯 JS 实现，不依赖安全上下文 |
| iOS Safari 文件访问 | 下载落到「文件」App，路径不直观 | 身份库（浏览器内）+ Web Share 导出，比找文件更可靠 |
| 首次连接信任 | 无证书体系 | 门户页展示服务器公钥指纹，要求用户核对 |

### 4. 本轮交付

- `GET /welcome`：客户端下载页 + 使用说明（连接、防火墙、身份文件、加密说明、房间/私聊/文件）。
- `GET /api/client-info`：返回客户端文件名、字节数、SHA-256、服务器地址与指纹，供门户页展示校验值。
- `GET /download/chatroom.html`：带 `Content-Disposition: attachment` 的单文件下载。
- 在线聊天按钮直达 `/`，无需下载；身份导入由客户端登录页「身份文件」区块完成，门户页给出图文步骤。

## 二、移动端 H5 适配与「方便管理 / 导出 / 导入用户信息」

### 1. H5 适配可行性：可行，纯 CSS + 少量 DOM 调整，无框架改动

现有客户端是零依赖单文件，改造成本低。适配清单：

| 项 | 做法 |
|---|---|
| 视口 | `viewport-fit=cover` + `width=device-width, initial-scale=1, maximum-scale=1`（防双击缩放） |
| 高度 | `100dvh` 替代 `100vh`，规避 iOS Safari 地址栏抖动 |
| 安全区 | `padding: env(safe-area-inset-bottom)` 保护底部输入栏 |
| 触摸目标 | 按钮/房间标签 ≥44 px，输入框 `font-size:16px` 防 iOS 自动放大 |
| 布局 | 侧栏改抽屉（遮罩 + 滑出），房间列表改横向可滚动标签条 |
| 多房间 | 标签条横向滚动 + 未读角标，避免占用竖向空间 |
| 文件 | 拖拽在移动端不可用，保留点击选取；`accept=".png,.pdf,.zip"` |
| 主屏 | 可选 PWA manifest；局域网 `http://` 非安全上下文，Service Worker 不可用，故**不做离线缓存** |

### 2. 移动端身份管理的真实难点

- 下载的 XML 会落到「文件」App / 下载目录，用户很难找到并再次选中；
- iOS Safari 沙箱 + 跨浏览器 localStorage 不共享；
- 多人共用一台设备、或一个人多个身份（大厅昵称 / 私聊身份）时，反复「选择文件 → 输口令」体验很差；
- 浏览器**无法静默写「当前目录」**（上一轮已说明），所以不能依赖文件系统做自动持久化。

### 3. 推荐方案：浏览器内「身份库 + 一键切换」（本轮实现）

| 能力 | 实现 | 对应需求 |
|---|---|---|
| 身份库 | `localStorage` 保存多份身份 XML 原文（加密文件保存密文），记录昵称/UID/服务器/创建时间 | 管理 |
| 导入 | 文件选择框读入 XML → 校验完整性 → 存入身份库；也可从登录页直接临时导入不入库 | 导入 |
| 导出 | 任一条目一键导出 `.xml`（Blob 下载），支持 Web Share API 分享到其它设备 | 导出 |
| 快速登录 | 顶栏「切换身份」→ 选条目 → 自动断开、恢复该身份、用挑战签名重连 | 在线切换 |
| 加密口令 | 加密身份切换时需输入口令，口令仅在会话内存缓存，不落盘 | 本地加密 |
| 删除/重命名 | 身份库条目逐条管理 | 管理 |

服务端配合：只保存公钥 + 身份哈希链留痕；同一 UID 重复登录由新会话接管（ADR-012 已修复），切换身份时不会残留旧会话状态。

### 4. 评估过但**未采用**的方案

| 方案 | 不采用原因 |
|---|---|
| WebAuthn / Passkey 绑定身份 | 需要 HTTPS 安全上下文，局域网 `http://IP` 不可用 |
| 云端同步身份文件 | 与「本地运行、零公网依赖」定位冲突，且把私钥交给第三方 |
| 静默写当前目录 XML | 浏览器沙箱禁止，只能下载或经 File System Access API 显式授权 |
| 二维码承载完整身份 XML | RSA-2048 私钥 PEM 约 1.7 KB，二维码过大且私钥暴露在屏幕上；仅用于短邀请码 |

### 5. 结论

服务端免下载聊天**可行且已具备**，只需补齐门户与说明；移动端**可完整适配**，身份管理不应依赖文件系统，而应采用「浏览器内身份库 + 一键切换 + XML 导入导出做跨设备迁移」。本轮按此实现，具体代码位置见 `docs/14-v4变更说明.md`。
