## 2. 协议与数据变更

```text
MSG.SERVER_CONFIG_UPDATE      = 'server_config_update'      服务端 → 客户端
MSG.ROOM_UPDATED              = 'room_updated'              服务端 → 客户端
MSG.NICKNAME_CHANGE           = 'nickname_change'           客户端 → 服务端
MSG.NICKNAME_UPDATED          = 'nickname_updated'          服务端 → 客户端
MSG.DIRECT_MESSAGE            = 'direct_message'            客户端 → 服务端
MSG.DIRECT_MESSAGE_BROADCAST  = 'direct_message_broadcast'  服务端 → 接收方

```

- 注册包 `inner.permanent` 新增布尔字段；`canonicalRegister()` 仍只签原有 5 个字段，`permanent` 由外层混合加密体保护，不参与签名串。
- 归档表新增 `e2ee` 标记：私聊密文以 `aad = 'dm|room|uid|seq|ts'` 落库，管理员只能看到「[端到端加密内容，服务端不可解密]」；历史消息回复同样带 `e2ee` 标记，客户端跳过解密。
- `identities.permanent` 列在 v4 已存在，v5 起成为身份链写入的唯一判据。

## 4. 架构决策（ADR-018 ~ ADR-021）

- **ADR-018 身份链只记正式用户**：临时用户与机器人仍需要数据库行做在线管理，但把它们写进哈希链只会放大链体积且没有审计价值；以 `permanent` 作为唯一判据，链上区块可稳定对应「可反复登录的真实身份」。
- **ADR-019 大厅直聊不建房间**：沿用当前房间的成员集合与在线状态，用「一次性 AES 密钥 + 接收方公钥封装」实现 E2EE；服务端只见密文，归档标 `e2ee`，管理员不可解密；与 v3 的 E2EE 私聊房间相比，省去房间创建/邀请码流程，符合「点击用户名即私聊」。
- **ADR-020 直聊 AAD 命名空间隔离**：`directAad = 'dm|room|uid|seq|ts'` 与公聊 `messageAad = 'room|uid|seq|ts'` 不同，使公聊密文无法被重放成私聊密文（反之亦然），GCM 标签校验直接拒绝跨命名空间篡改。
- **ADR-021 配置/版权走广播而非刷新**：名称、版权属于展示态配置，改动频繁且无需重启；保存后由服务端主动推送 `SERVER_CONFIG_UPDATE`，客户端即时更新标题与底栏，避免用户停留在旧页面造成信息不一致。端口与监听地址仍是启动参数，需进程级重启。

## 5. 安全边界（不变 / 新增）

- 服务端仍持有普通房间的会话密钥与归档主密钥，**普通公聊可被管理员解密查看**（v3 起的设计，未改变）。
- 大厅直聊私聊内容服务端**不可解密**：一次性 AES 密钥只用接收方公钥封装；服务端归档为 `e2ee` 密文，历史接口只回元数据 + `e2ee` 标记。
- 身份文件（含私钥）**永不上传**，正式用户身份由 RSA-PSS 挑战签名恢复（ADR-015 不变）。
- 直聊仍有 `seq` 递增防重放、30 条/秒频率限制、密文长度上限与目标成员在线校验。
- 私聊模式下禁用附件：文件链路复用房间密钥，与「仅接收方可解密」的语义不一致，故明确关闭并提示。

## 7. 使用要点

1. **成为正式用户**：登录页「身份信息包」右栏勾选「勾选即注册为正式用户」，可同时设置本地加密口令 → 连接成功后自动下载 `.xml`，请妥善保存；以后在左栏导入即可复用同一身份，并支持在线改名。
2. **临时用户**：不勾选即生成新身份，昵称自动带 6 位随机时间戳（琥珀色），改名后时间戳不变；退出即失效，不写身份链。
3. **大厅私聊**：点击右侧成员列表中的用户名 → 自动切到「私聊」，紫色斜体气泡表示仅双方可见；点 `dm-chip` 的 ×、切回「公聊」或按 `Esc` 返回公聊；私聊不支持附件。
4. **管理端**：「服务器配置」逐字段有说明；「版权信息管理」可改文字与链接；「用户管理」勾选「只看在线用户」过滤；「房间管理」可改名并即时同步给所有客户端。
5. **版权头**：新增源码文件后运行 `node tools/stamp-copyright.js`，发布前用 `node tools/stamp-copyright.js --check` 校验。

## 8. 已知限制

- 直聊密文归档后，接收方若更换身份文件（新私钥），历史私聊密文将无法再解开——E2EE 的必然结果。
- 直聊未做多设备同步：同一身份在别处登录会接管会话，之前的直聊上下文不迁移。
- 服务端名称/版权广播只覆盖**当前在线**连接；离线客户端下次登录时从 `REGISTERED` 回执获取最新值。
- 身份链为单节点许可链，无 PoW / 共识（ADR-007 不变）；`chainPolicy: formal-users-only` 只约束写入对象，不改变哈希链与签名校验机制。
