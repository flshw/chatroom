## 二、必须说明的架构取舍

1. **身份模式改为双轨**：v2 是「每次登录全新身份」。v3 默认仍为临时身份；勾选「保存身份文件」或导入旧 XML 则登记为持久身份并复用 UID。这样新旧需求都成立。
2. **「区块链」的真实含义**：局域网单机服务端没有多节点，PoW/共识/P2P 不增加任何信任（服务端是唯一写入者）。因此落地为**哈希链 + 服务器签名的可验证账本**，任何事后篡改都能被 `verify()` 检出。这是单节点许可链，不是公链。
3. **服务端绝不保存用户私钥**：链上只存 UID、昵称、**公钥**、浏览器 ID、状态与授权。私钥只存在客户端 XML 文件（可用口令加密）。否则任何拿到服务器的人都能冒充用户登录。用户的「密钥保存」需求由客户端 XML 承担。
4. **私聊 E2EE 与「管理员查看私聊」的边界**：两者严格冲突。本版按「只有双方可见」优先——管理员只能看到谁在何时发了多长的密文，看不到内容。这是对需求 4 与需求 8 的明确取舍。
5. **浏览器写文件限制**：浏览器不能静默写到「当前目录」。XML 通过 Blob 下载到浏览器默认下载目录（或用户自行另存到当前目录），导入通过 `<input type="file">`。若后续需要真正选目录写入，可加 File System Access API（Chromium 系、需用户授权）。
6. **重启语义**：管理页按钮是**进程内软重启**（重建全部状态与监听，不换 PID、端口不变）。好处是管理页不会因端口变化失联、跨平台行为一致；若要应用新端口或升级代码，仍需重启 `npm start` / systemd 服务。
7. **文件走 HTTP 而非 WebSocket**：现有帧上限 64 KB，8 MB 文件改为 `POST /api/file/upload`（HTTP body 上限 24 MB）。文件内容在客户端加密，服务端只做白名单校验与转发。

联调中发现并修复的真实缺陷：**同一持久身份重复登录时，后一个会话断开会错误清除前一个会话的用户状态**（`Hub.detach`）。现改为单会话接管语义：新登录主动关闭旧连接，`detach` 仅清理属于自己会话的状态（ADR-012）。

## 五、使用要点与已知边界

- **管理员初始口令**：首次启动在服务端控制台打印（本机为 `tpSb5rPJvwUPwgmE`），也会写入 `server/logs/`；请登录后立即在管理页「概览 → 管理员凭据」修改，或下载私钥改用非对称登录。口令不可从 `admin-keys.json` 反推。
- **身份文件**：登录页展开「身份文件 · 保存 / 导入」，勾选保存后连接成功会自动下载 XML；建议设置本地加密口令。再次登录时选择该文件（加密文件需填同一口令）即可恢复身份。
- **私聊**：点击成员列表中的成员发起，房间名带 🔒，服务端不持密钥。
- **文件**：点「附件」选择 png/pdf/zip；png 在气泡内显示缩略图、点击放大；pdf 点「预览」在模态框内嵌查看；zip 点「下载」。
- **邀请码**：点「复制邀请码」得到 `CR1.` 开头的完整码，粘贴到登录页邀请码框可自动填 IP/端口并直达房间。
- 边界：`/api/invite/create` 与文件上传用 `uid` + 房间成员关系做校验（非强认证，适用于可信局域网）；E2EE 私聊换身份文件后无法解密历史密文（符合 E2EE 语义）；管理页 RSA 登录需要 `/assets/forge.min.js`，已随服务端目录本地化；软重启不应用端口变更。
