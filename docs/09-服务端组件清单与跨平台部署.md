## 一、组件清单

### A. 运行时环境（1 项）

| 组件 | 版本 | 用途 | 平台相关性 |
|---|---|---|---|
| Node.js | 实测 v22.22.2；`package.json` 声明 `>=22` | 提供 `http` / `fs` / `path` / `os` / `Buffer` / `URL` / 定时器 | 官方提供 Windows / Linux / macOS 的 x64 与 ARM64 构建 |

`npm` 仅在首次安装依赖时需要；**运行时不需要 npm、不需要网络、不需要 Python、不需要编译器**。

### B. 第三方库（3 个，全部纯 JS，无原生编译）

| 包 | 实际安装版本 | 体积 | 用途 | 许可证 |
|---|---|---|---|---|
| `ws` | 8.23.0 | ~110 KB | WebSocket 服务端、帧解析、`/ws` 升级、心跳 | MIT |
| `node-forge` | 1.4.3 | ~260 KB | RSA-2048 密钥对生成、RSA-OAEP / RSA-PSS、AES-256-GCM、SHA-256、PEM 编解码、安全随机数 | BSD-3-Clause / GPL-2.0 |
| `sql.js` | 1.16.0 + `sql-wasm.wasm` | JS ~40 KB + WASM 673 KB | SQLite 微型数据库（WASM 实现），房间/消息/元数据三张表 | MIT |

**关键事实**：`find server/node_modules -name "*.node"` 结果为空 —— 全部依赖均为纯 JavaScript 或 WASM 字节码，**不存在需要 `node-gyp` 编译的原生插件**。这也是跨平台免编译的根本原因。刻意未采用 `better-sqlite3`（需原生编译）、`express`（`node:http` 已足够）。

## 二、能否在 Windows / Linux 上运行

**结论：可以，两端都能直接运行，无需修改任何代码。**

| 平台 | 结论 | 依据 |
|---|---|---|
| Windows 10/11 x64 | ✅ **已实机验证** | 本机 Node 22.22.2 启动、22 项端到端测试通过 |
| Linux（Ubuntu / Debian / CentOS / RHEL，x64 或 ARM64） | ✅ **可运行** | 无平台相关代码的静态扫描 + 等价部署实测（见下） |
| macOS | ✅ 可运行 | 同上 |

### 支撑证据

1. **静态扫描**：全部源码使用 `path.join` / `path.resolve` / `__dirname` 构造路径，无 `C:\`、`D:\` 盘符、无反斜杠硬编码、无 `child_process` / `spawn` / 平台专属命令、无 `process.platform` 分支。
2. **无原生模块**：三个依赖均为纯 JS / WASM；`sql-wasm.wasm` 是架构无关的 wasm32 字节码，x64 与 ARM64 均可执行。
3. **源码格式**：全部为 UTF-8 + LF 换行，`node --check` 逐个通过，无 CRLF、无 BOM、无路径大小写敏感问题（代码中的路径全小写）。
4. **进程信号**：`SIGINT`（Ctrl+C）与 `SIGTERM`（systemd / kill）在两端均会触发数据库落盘。
5. **等价部署实测**：把修复后的 `server/` 单独拷到一个**不含 `client/`、`vendor/`、`docs/`、`tools/`** 的空目录，用 `--port 8099` 启动 —— 健康检查通过、`GET /` 返回 332,216 字节客户端页、`GET /admin` 返回配置界面，**完整 22 项端到端测试 22/22 通过**（含非对称注册、密钥交付、密文收发、防重放、归档解密、代理中继）。这等价于把它拷到另一台 Linux 机器上运行。
6. 本机为 Windows，**未在真实 Linux 实机执行**；上述结论基于平台无关性扫描与独立目录等价实测，Linux 侧差异仅剩防火墙与进程守护方式（见下）。

### 本次修复的可移植性缺陷（ADR-009）

初次做独立目录实测时启动失败：`Cannot find module '../../shared/protocol'`。原因是 4 个服务端源文件 `require('../../shared/protocol')` 引用了工作区根部，导致 `server/` 单独分发时不可启动。已修复：

- 新增 `server/src/protocol.js`，4 处 `require` 改为 `require('./protocol')`；
- `tools/build-client.js` 每次构建以 `shared/protocol.js` 为权威源，自动把字节一致的副本同步到 `server/src/protocol.js`，避免两份协议常量分叉；
- `main.js` 日志目录由工作区根部 `logs/` 改为 `server/logs/`，部署包完全自包含、且不会向只读父目录写日志；
- 启动横幅的防火墙提示改为 Windows / Linux 通用文案。

## 三、两平台部署步骤

### Windows

```bat
cd /d D:\chatroom\server
:: 若随包已带 node_modules 可跳过
npm ci --omit=dev
node src/main.js --port 8080
```

放行防火墙（管理员 CMD 执行一次）：

```bat
netsh advfirewall firewall add rule name="ChatRoom 8080" dir=in action=allow protocol=TCP localport=8080
```

### Linux

```bash
# 1. 准备 Node.js（发行版源版本过低时用 NodeSource / nvm 装 22.x）
sudo apt install -y nodejs npm          # Debian/Ubuntu；RHEL 系用 dnf install nodejs

# 2. 放置部署包并启动
sudo mkdir -p /opt/chatroom
sudo cp -r server /opt/chatroom/
cd /opt/chatroom/server
# 若随包已带 node_modules 可跳过；无网络环境直接整目录拷贝即可
[ -d node_modules ] || npm ci --omit=dev
CHATROOM_PORT=8080 node src/main.js     # 或 node src/main.js --port 8080

# 3. 放行端口
sudo ufw allow 8080/tcp                                        # Ubuntu/Debian
# 或：sudo firewall-cmd --add-port=8080/tcp --permanent && sudo firewall-cmd --reload

# 4. 保护私钥
sudo chmod 600 /opt/chatroom/server/data/keys.json
```

后台常驻（systemd，`/etc/systemd/system/chatroom.service`）：

```ini
[Unit]
Description=ChatRoom LAN Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/chatroom/server
Environment=CHATROOM_PORT=8080
ExecStart=/usr/bin/node src/main.js
Restart=on-failure
User=chatroom

[Install]
WantedBy=multi-user.target
```

`sudo systemctl daemon-reload && sudo systemctl enable --now chatroom`；停止时 systemd 发 `SIGTERM`，服务端会自动把加密归档落盘。

## 四、平台差异与注意事项（均不阻塞运行）

| 事项 | 说明 |
|---|---|
| 防火墙 | Windows 用高级安全防火墙入站规则；Linux 用 `ufw` / `firewalld` / `iptables` |
| 低端口权限 | Linux 下绑定 <1024 端口需 root 或 `CAP_NET_BIND_SERVICE`；默认 8080 规避 |
| 控制台横幅 | 使用 Unicode 框线字符，Linux UTF-8 终端正常；Windows 传统 CMD 建议 `chcp 65001` 或用 Windows Terminal |
| 网卡命名 | `os.networkInterfaces()` 跨平台，Linux 显示 `eth0` / `enp0s3` 而非「以太网」，仅影响提示文字 |
| 文件权限 | Linux 建议 `keys.json` 设为 600，部署目录属主设为运行服务的非 root 用户 |
| 端口占用 | 两端统一报错 `EADDRINUSE`，用 `--port` 或 `CHATROOM_PORT` 换端口 |
| 时间同步 | 注册包有 60 秒时间戳容差，跨机器若时钟偏差过大会被判为防重放拒绝；建议启用 NTP |
| Node 版本 | `engines` 保守声明 `>=22`；代码仅用 CommonJS + ES2020，理论上 Node 18+ 亦可，但未在 18 上实测 |
