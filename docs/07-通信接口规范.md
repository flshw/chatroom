# 通信接口规范

协议版本 `v=1`，所有 WebSocket 帧为 JSON 文本，顶层结构：

```json
{ "v": 1, "type": "message", "id": "m_xxx", "data": { } }
```

所有二进制字段（密文、IV、tag、签名、密钥）统一 base64。

## 1. 消息类型总表

| type | 方向 | 说明 |
|---|---|---|
| `hello` | C→S | 请求服务器公钥与挑战码 |
| `welcome` | S→C | 下发公钥、指纹、挑战码、时间戳、盐 |
| `register` | C→S | RSA-OAEP 加密注册包 |
| `registered` | S→C | 注册成功，下发 UID 与被封装的大厅密钥 |
| `error` | S→C | 错误，`data.code` 见错误码表 |
| `notice` | S→C | 系统提示（成员进出、房间事件） |
| `room_list` | C→S | 请求房间列表 |
| `room_list_data` | S→C | 房间列表 |
| `room_create` | C→S | 创建房间 `{name, private}` |
| `room_join` | C→S | 加入房间 `{roomId}` 或 `{invite}` |
| `room_joined` | S→C | 加入成功，含该房间被封装的会话密钥与成员列表 |
| `room_leave` | C→S | 离开房间 `{roomId}` |
| `room_members` | S→C | 房间成员变更 |
| `message` | C→S | 加密消息 envelope |
| `message_broadcast` | S→C | 转发加密消息 envelope（原样） |
| `history` | C→S | 请求房间历史 `{roomId, limit}` |
| `history_data` | S→C | 历史 envelope 数组 |
| `key_rotate` | S→C | 预留：房间密钥轮换 |
| `ping` / `pong` | 双向 | 心跳 |

## 2. 关键报文

### welcome（S→C）
```json
{ "v":1, "type":"welcome", "data": {
  "pubKey": "-----BEGIN PUBLIC KEY-----\n...",
  "fingerprint": "a1b2c3d4e5f60718",
  "challenge": "b64(16 bytes)",
  "salt": "b64(16 bytes)",
  "ts": 1763100000000,
  "version": "1.0.0"
}}
```

### register（C→S）
```json
{ "v":1, "type":"register", "data": { "blob": {
  "wrappedKey": "b64(RSA-OAEP(S_pub, b64(K_reg)))",
  "iv": "b64(12)", "ct": "b64(n)", "tag": "b64(16)"
} } }
```
> 注册包含公钥 PEM 与签名，超过 RSA 单次加密长度上限，故采用混合加密：随机 `K_reg` 由 `S_pub` 封装，注册包正文由 `K_reg` 做 AES-256-GCM（AAD 固定为 `chatroom-register-v1`）。
`inner`：
```json
{ "username":"alice", "browserId":"fp_xxx", "ts":1763100000123,
  "nonce":"b64(16)", "challenge":"...", "clientPub":"-----BEGIN PUBLIC KEY-----...",
  "sig":"b64(RSA-PSS(C_priv, SHA256(username|browserId|ts|nonce|challenge)))" }
```

### registered（S→C）
```json
{ "v":1, "type":"registered", "data": {
  "uid":"hex64", "username":"alice",
  "wrappedLobbyKey":"b64(RSA-OAEP(C_pub, b64(K_lobby)))",
  "server": { "name":"ChatRoom", "maxRooms":50, "historyEnabled":true }
}}
```

### message / message_broadcast
```json
{ "v":1, "type":"message", "data": {
  "room":"r_abc123", "seq":12, "ts":1763100000999,
  "iv":"b64(12)", "ct":"b64(n)", "tag":"b64(16)"
}}
```
AAD 约定：`${room}|${发送者uid}|${seq}|${ts}`。服务端广播时补上 `from` 字段（即发送者 UID），接收方据此重建 AAD 后解密；`from` 本身不出现在客户端发出的上行报文中。

### room_joined（S→C）
```json
{ "v":1, "type":"room_joined", "data": {
  "room": { "id":"r_abc123", "name":"技术讨论", "private":false, "invite":"ABCD-1234" },
  "wrappedKey":"b64(RSA-OAEP(C_pub, b64(K_room)))",
  "members": [ {"uid":"hex64","username":"alice"} ]
}}
```

## 3. 错误码

| code | 含义 |
|---|---|
| `E_BAD_VERSION` | 协议版本不匹配 |
| `E_BAD_ENVELOPE` | 报文格式错误 |
| `E_REGISTER_FAILED` | 注册失败（解密/验签/挑战码/时间戳/nonce 任一不通过，不细分） |
| `E_REPLAY` | 消息序号回退或重复 |
| `E_NOT_IN_ROOM` | 未在目标房间 |
| `E_ROOM_FULL` | 房间人数或房间数达上限 |
| `E_ROOM_NOT_FOUND` | 房间或邀请码不存在 |
| `E_FORBIDDEN` | 权限不足（如私聊房间第三方加入） |
| `E_RATE_LIMIT` | 频率限制 |
| `E_INTERNAL` | 服务端内部错误 |

## 4. HTTP 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` | 客户端页面（托管 `server/public/chatroom.html`） |
| `GET` | `/admin` | 服务端配置界面 |
| `GET` | `/api/server-info` | 公钥、指纹、IP、端口、在线数、房间数 |
| `GET` | `/api/config` | 读取服务端配置 |
| `POST` | `/api/config` | 更新配置（端口需重启生效） |
| `GET` | `/api/archive/rooms` | 归档房间列表 |
| `GET` | `/api/archive/messages?room=&limit=` | 服务端解密后的归档消息（仅管理界面） |
| `GET` | `/api/health` | 健康检查 |
| `POST` | `/relay` | 代理中继：`{clientId, envelope?}` → `{messages:[...]}` |
| `GET` | `/ws` | WebSocket 升级端点 |

CORS：所有 `/api/*` 与 `/relay` 返回 `Access-Control-Allow-Origin: *`，显式放行 `Origin: null`（`file://` 客户端）。

## 5. Session 抽象

WebSocket 与 HTTP 中继共用同一 `Session` 接口：

```js
class Session {
  send(envelope)      // WsSession -> ws.send()；RelaySession -> push 到队列
  close(reason)       // 清理
  get isOpen()
}
```

所有入站 envelope 统一交给 `handleEnvelope(session, envelope)`，保证两种接入方式行为完全一致。

## 6. 状态机

```
[连接] --hello--> [等待注册] --register(校验通过)--> [已认证]
[已认证] --room_join/room_create--> [房间内] --message--> [房间内]
[房间内] --room_leave--> [已认证]
任意状态 --断开/超时--> [销毁，清理成员与密钥引用]
```

心跳：服务端每 30s 发 `ping`，60s 无 `pong` 断开；中继 Session 以最后一次 `/relay` 请求时间作为活跃判据，120s 无请求则回收。
