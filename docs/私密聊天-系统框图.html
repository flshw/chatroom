图 1　总体系统架构

发起人走 HTTPS 门户申请并下载专属客户端；服务端分控制面与数据面；朋友用单文件 HTML 只与数据面建立密文通道。HTML 文件由发起人线下自行分发，服务端不参与。

控制面 / 数据面 / 客户端线下分发路径（不可控）

图 2　房间生命周期状态流转

TTL 默认 24 小时、上限 72 小时，从签发时刻起算；定时器与每次请求惰性检查双保险，进程重启后扫描补清理，销毁后不可恢复。

图 3　内置凭证分层与信任边界

三类内置数据职责严格分离：准入、加密、完整性。服务端只转发密文；但拿到 HTML 文件等于同时获得准入与解密能力，这是本设计固有的安全边界。

硬阻塞决策 Q-02加密模型 A / B / C 决定签发器与加密核心怎么写，建议 B「生成即遗忘」。
硬阻塞决策 Q-12现有自签 CA 朋友不会信任，必须换公网可信证书，否则「只填昵称」不成立。
最大的环境风险file:// 下 Origin 为 null、音视频权限不稳定，需提供在线 HTTPS 备选入口。
