# 需求规格说明书 v2

## 1. 产品目标

局域网内可用的端到端加密聊天室：一个独立服务端进程 + 一个轻量客户端页面，通过 IP 地址与端口连接，支持房间群聊与一对一私聊，聊天数据由服务端加密留存且仅服务端可查看。

## 2. 运行环境

| 项 | 要求 |
|---|---|
| 服务端 | Node.js >= 22，`npm install` 安装依赖，监听 TCP 端口 |
| 客户端 | 现代浏览器（Chrome / Edge / Firefox），本地 `file://` 或 `http://` 均可 |
| 网络 | 同一局域网；可选 HTTP 中继代理 |
| 外部依赖 | 运行时零公网依赖，所有库已本地化 |

## 3. 功能需求

### 3.1 服务端

| 编号 | 需求 |
|---|---|
| S-01 | 首次启动自动生成 RSA-2048 密钥对，私钥加密保存于 `server/data/`，公钥对外公布 |
| S-02 | 启动后枚举并打印全部内网 IPv4 地址与监听端口 |
| S-03 | 通过 HTTP 静态托管客户端页面与管理界面 |
| S-04 | 通过 WebSocket 接受客户端接入，维护在线连接与心跳 |
| S-05 | 处理非对称注册：解密注册包、校验挑战码与时间戳、防重放 |
| S-06 | 生成 `UID = SHA-256(浏览器ID \| 时间戳 \| 盐 \| 挑战码)`，每次登录全新 |
| S-07 | 为每个房间生成独立 AES-256 会话密钥，用成员各自公钥封装后单独交付 |
| S-08 | 密文消息路由：群聊广播、私聊定向；服务端不解密业务消息内容 |
| S-09 | 房间管理：创建、邀请码加入、成员列表、退出、解散 |
| S-10 | 聊天数据写入微型数据库（SQLite），用归档主密钥 AES-256-GCM 加密 |
| S-11 | 归档主密钥用服务器公钥封装后落盘，仅服务端私钥可解封 |
| S-12 | 提供 Web 配置界面：端口、房间上限、历史开关、归档查看、密钥指纹展示 |
| S-13 | 提供 `/relay` 密文中继端点，支持代理接入 |
| S-14 | 结构化日志输出到 `logs/` |

### 3.2 客户端

| 编号 | 需求 |
|---|---|
| C-01 | 初始界面仅需：用户名、服务器 IP、端口；代理地址为可选折叠项 |
| C-02 | 连接后自动完成：取服务器公钥 → 生成临时 RSA 密钥对 → 加密注册 → 挑战应答认证 |
| C-03 | 接收并用自身私钥解封房间会话密钥，之后所有聊天走 AES-256-GCM |
| C-04 | 浏览器 ID 由 Canvas/WebGL/Audio 指纹 + 本地随机盐构成，与时间戳一起形成唯一身份码 |
| C-05 | 房间列表、创建房间、邀请码加入、一对一私聊发起 |
| C-06 | 消息收发、成员列表、连接状态、系统提示 |
| C-07 | 支持代理/中继地址配置，密文经中继转发 |
| C-08 | 断线自动重连（重新注册，获得全新身份码） |
| C-09 | UI 简洁大气：留白充足、无多余装饰、响应式适配 |
| C-10 | 可打包为独立单文件 `chatroom.html`，本地双击即可运行 |

## 4. 非功能需求

- **机密性**：传输、存储均为密文；服务端、代理、旁路监听者都无法读取消息明文。
- **完整性**：AES-GCM 认证标签 + 消息序号，防篡改与重放。
- **性能**：单服务端支持 50 并发连接、每房间 30 成员；RSA 运算仅在连接建立与加入房间时发生。
- **可用性**：服务端异常退出后重启可恢复加密归档数据。
- **可维护性**：两端共用协议常量与加密算法封装，源码分文件，构建脚本产出单文件客户端。

## 5. 不在本版范围

- 公网穿透 / NAT 打洞
- 文件与图片传输、语音视频
- 用户账号体系与密码登录（身份每次全新，设计上不需要）
- 前向保密（PFS）与密钥轮换（预留 `KEY_ROTATE` 协议字段）
- 移动端原生 App
